A research direction of the HumeBot project

Open-Weight Model Research

Alongside its instructor-directed educational work, HumeBot studies whether an open-weight language model, one whose weights can be run on research computing and held fixed, can meet the project's standards of textual accountability, and what that would take.

Research, not deployment. No model, open-weight or commercial, is qualified for classroom use, and no model or deployment pathway has been chosen for teaching.

Why open weights

  • Reproducibility. A study can name the exact model version it used and be run again against identical weights, independent of a provider's update schedule.
  • Experimental control. The model can be held fixed while one part of the system changes. On research computing it runs locally, with no outside service in the loop, and everything it was given is logged.
  • Possible institutional hosting. An open-weight model could in principle run inside institutional infrastructure, which may matter for student privacy and institutional control. Whether that can work for a course has not been established.

The model and the computing

Most of this work uses Gemma 4 31B, an open-weight instruction model from Google, run through HumeBot's three-stage harness.

  • The formal qualification attempt of October 2026, and a series of development studies that month, ran on GPUs at the University of Minnesota's Minnesota Supercomputing Institute (MSI). The model was served on MSI's own hardware, not through an outside service.
  • Earlier controlled comparisons used the same model through the research inference service of the Argonne Leadership Computing Facility.

What has been studied

Evidence selection

Can the model find the passages an answer needs? In a 24-question study, with all 216 units of the corpus in view and no search index, the evidence-selection stage found evidence for 61 of 63 requirements. Its clearest weakness was relating passages: it could hold the right two passages, mark the relation between them unresolved, and so decline to answer. Later development experiments on MSI found that giving the selector more information about the question changed which passages it chose, but not how much of the essential evidence it found.

Explanation quality and inferential reasoning

On a 36-question development set, the open-weight system delivered verified answers to 35. In development grading, fewer than half were free of a material problem, and four contained serious scholarly errors. Keeping the rest of the system the same, a much larger open-weight model (Qwen3.5-397B) as the writer repaired some omissions of evidence. It did not repair errors of scope, in which an answer misstates how conditional or provisional one of Hume's claims is.

Comparisons across models

  • Two open-weight models. On the same frozen questions, reviewers judged gpt-oss-120b's interpretations the richest when it was prompted directly, but most of its citations were faulty, and inside the harness it answered only half the questions. Gemma 4 31B remained the strongest configuration tested, which did not qualify it.
  • Open-weight and frontier. In the same harness, a frontier model, Claude Opus 5.5, reached through its provider's service, produced only exact citations in that sample: all 442 were exact. Prompted directly, it quoted exactly in that sample too, and the harness did not improve its fidelity. In a small pilot on five questions chosen because Gemma had struggled with them, the frontier model's answers were better, with or without the harness. That sample was chosen to probe weaknesses, so it shows where the open-weight model falls short, not by how much.

Verification is not correctness

In studies with Gemma 4 31B, the harness produced no faulty citations: none of 89 in a 24-question comparison, none of 250 across three repeated runs, and none of 238 on 60 newly written questions. These results establish exactness in those experiments; they are not a general guarantee of how any model will perform. Prompted directly with the whole text, the same model quoted exactly only about 86–92% of the time. The difference is architectural. The software builds every displayed quotation from the controlled text, so a misquotation is caught and withheld rather than shown.

This verification concerns Hume's words and where they stand. It does not show that a passage supports what an explanation says, or that the explanation reads Hume correctly: an answer can quote exactly and still misread him. Interpretive quality is judged by people, and the experiments have not shown that the harness makes the model interpret Hume better.

Qualification and its limits

In October 2026, a frozen configuration built on Gemma 4 31B went through a formal qualification attempt on MSI, running all 170 of a set of newly written questions, with repeats. The attempt returned NOT_ELIGIBLE at its evidence-eligibility gate, the check that decides whether a run's evidence can go forward to scholarly review. No scholarly review followed, so it established neither a PASS nor a FAIL. The question set is now used, and a redesigned attempt, which would need a fresh set of similar size, exists only as a plan. No system is qualified.

Beyond exact citation in these experiments, what they have established is mostly a set of limits:

  • quotation fidelity is a weakness of the model itself, which the harness contains but does not cure;
  • omissions, relating passages, and keeping the scope of Hume's claims are recurring weaknesses in the open-weight model's explanations;
  • verification cannot tell when an exactly quoted passage is the wrong evidence for a claim.

All of these results come from small samples and particular model versions. They are directional, not population estimates.

Post-training

Post-training adapts a model after its original training, for example by supervised fine-tuning or preference learning. These methods can update the model's own weights or, with LoRA, train a small set of added adapter weights: LoRA generally leaves the base model's weights frozen. HumeBot treats post-training as a research question, governed by rules set in advance:

  • training may target how a model uses evidence, reasons and explains, learning from reviewed expert feedback, but never Hume's text itself or memorized answers;
  • any fine-tuned model or trained adapter is a new candidate, to be frozen and evaluated afresh;
  • training, development and evaluation material are kept apart, so that no test is contaminated.

The first exploratory study, in October 2026 on MSI, tried to build training examples automatically from public question-answering datasets unrelated to Hume. It stopped before any training. The datasets' labels were adequate for checking an answer, but in many cases did not establish the relation HumeBot's evidence standard requires, so the procedure could not produce enough trustworthy examples. A design for LoRA-based training was drafted, but no method has been adopted.

The October study produced no trained model or adapter, and no improvement from post-training has been demonstrated in HumeBot.

How this complements the instructor-directed work

The instructor-directed work asks whether an instructor's reconstruction of an argument can improve explanations while keeping Hume's text, the course's reading and the model's explanation distinct. The open-weight work asks whether a model that can be hosted, inspected and held fixed can meet the same textual standards, and where it falls short.

The harness is not tied to one model, so what one line learns about evidence, explanation and failure informs the other. The two lines need not use the same model. Which model would serve a course, and whether it would be hosted by the University or reached through a commercial service, has not been decided.
